# `src/app/`

The root component's wiring: its Model, Commands, Mounts, Subscriptions, the root view that places each screen and draws its children, the root's own Dialogs, and every root handler with the Steps they share (`update/`).

Every module in this folder has its row below, its path from this folder (`bun run lint` fails a module no row names, and a row naming a file that is gone). Tests are not listed: each sits in the `__tests__/` folder beside the code it tests.

## At the top

| File                                       | What it holds                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model.ts`, `entry.ts`                     | The Model and its Schema types; the page entry: `Application` mounted on the page with `ApplicationLayer`                                                                                                                                                                                                                                                                 |
| `main.ts`, `message.ts`                    | `init`, and `update`: `ApplicationDef.update` over the one exhaustive handler record (the root's own frame and seed Messages, then each group's handlers spread in), combined with the after-message Steps; the root's Message union, one flat join of every group's cases (each group in the folder of the feature that sends it, co-op's and the children's events too) |
| `component.ts`                             | `ApplicationDef`, the root component as defined (`Html.component`: its name, Model, and Message), and the view aliases a feature types against (`ApplicationViewBuilder`, `ApplicationHtml`, `ApplicationMount`)                                                                                                                                                          |
| `block.ts`, `commands.ts`, `services.ts`   | `ApplicationNoDeps`, `ApplicationDef.make` over init, update, view, Subscriptions, and Mounts, and `Application`, it with its Command services provided (the tests and the audit harness provide their own); `CommandsLayer`, every root `Command.Service`'s layer; `ApplicationLayer`, the services the Commands use                                                     |
| `boot.ts`, `subscriptions.ts`, `mount.ts`  | The Commands init starts (`bootCommands`): reading the save, seeding, a visit id, device checks, load steps; Subscriptions: frames, the co-op room's frame, keys, pointers, page events, sync, the update check; the game surface's Mounts and SHARE's                                                                                                                    |
| `pureApp.ts`                               | The root's init, update, view, and Subscriptions as plain functions, with the whole start Model, for the tools that play the game (the balance bot, the determinism tools, the audit harness, the sprite atlas)                                                                                                                                                           |
| `view.ts`, `views/layers.ts`, `styles.css` | The root view and status text; the world's and the overlay's elements and what they are handed; the page styles                                                                                                                                                                                                                                                           |

## `frame/`

| File                                    | What it holds                                                                                                                                                                                                                                                                                                                 |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `frame/runReset.ts`, `menus/dialogs.ts` | Every field of one run, reset when a run starts and on going home (`returnHome`); the root's own Dialogs, each ui-kit's Dialog through `dialogShellView` (the MANOR hand, the menu panel with the Munchopedia and the Proof Shelf in it, the iPhone guide, the update greeting) around the insides their screen draws         |
| `frame/frame.ts`, `frame/runFlow.ts`    | The client's frame: ticks, intent, the lean, cosmetics (callouts, the trap notice), a round's end; starting and resuming a run                                                                                                                                                                                                |
| `frame/frameGate.ts`                    | The frame gate: a display frame's time held until the frames held owe the sim a tick, so a 90 or 120 Hz screen draws at most about 60 frames a second; both animation frame Subscriptions go through it; the title and its menus and lobbies go at a menu's pace, at most 30 frames a second (`gateMenuFrame`, `framePaceOf`) |

## `menus/`

| File                  | What it holds                                                                                                                                                                                                                                 |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `menus/menuState.ts`  | `menuState(model)`, which menu is up, derived and never stored, and its gates                                                                                                                                                                 |
| `menus/rootDialog.ts` | The root's dialogs as an effect-machine machine (`rootDialogMachine`, `stepRootDialog`): Shut, or the one dialog up, opened only from Shut and closed only by its own name; `DialogName`, and `isRootDialogOpen` for the views that draw each |
